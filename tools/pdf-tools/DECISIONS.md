# PDF tools: design decisions

Tool-specific intent and decisions, newest first. Site-wide principles are in
[`docs/PRINCIPLES.md`](../../docs/PRINCIPLES.md).

## Intent

For anyone who needs to change or convert a PDF and doesn't want to hand the file to a stranger's server:
contracts, payslips, medical letters, ID scans. It answers "can I do this common PDF job without uploading?".

Owner's requirements (16 November 2026), kept here so they aren't lost:

- **All processing happens locally in the browser. Nothing is ever uploaded to any server.** This is critical and
  outranks every feature. If a feature can't be done locally, it isn't offered.
- Conversions both ways between PDF and: Word and other document formats; PowerPoint and other slide formats;
  images (PNG, TIFF, JPEG, BMP, possibly SVG); Excel and other spreadsheet formats; text files; HTML.
- Editing: rearrange, duplicate and remove pages; resize the images in scanned PDFs separately from the page size;
  scale page size with contents; compress with a wide range of options and an estimate of the new size; split;
  extract; merge; edit content (add and remove text, formatting, resize and rotate, the same for images).
- Download the results, and also download settings that let the visitor re-apply their work and carry on later,
  without anything being stored on a server.

It deliberately does not: keep files between visits, offer accounts, or claim Word-perfect conversions.

## Decisions

| Date | Decision | Reason |
|---|---|---|
| 2026-11-17 | Watermark is text only for now, drawn on top of the page, and the page says it is a label that can be removed, not protection | Drawing behind existing content and picture watermarks are follow-ups; claiming protection would mislead |
| 2026-11-17 | Page numbers (and later the watermark) are "stamps": save options applied to every page as it will finally be seen, after turning and resizing, drawn with the same code as added text (`web/stamps.ts`). The task shows a live preview built as a real PDF | Same size and place on every page whatever its rotation; one drawing path to test; what is previewed is what is saved |
| 2026-11-16 | Protect PDF sets one password that grants full access, encrypts with the library's default (AES-256), and is the last step applied to a file. The password is never stored, including in the settings file | Simple to understand; separate "owner" restrictions are not real security, since this very tool removes them |
| 2026-11-16 | Unlock PDF only opens files with a password the visitor supplies; it never guesses | It is for people's own files |
| 2026-11-16 | The tool list follows ilovepdf.com's, built one small chunk at a time (queue in `ROADMAP.md`). Tools that need a server (AI summary and translation, phone-to-browser scanning, requesting signatures, web address to PDF) are listed on the home page as not offered, with the reason | Owner's request, and local-only outranks parity |
| 2026-11-16 | Home grid uses their categories with filter buttons; unbuilt tools sit greyed inside their category | Owner's request; people look for a tool where they expect it |
| 2026-11-16 | Two stronger compression levels added: Extreme (pictures at 72 dpi, 30% quality, text kept) and Maximum (whole pages redrawn as pictures, with the text-loss warning shown) | Owner asked for more extreme options in addition to the existing ones |
| 2026-11-16 | Edit PDF (first part) adds text and pictures only. No "cover with a box" tool is offered | A covered word is still in the file and can be copied out; offering it would look like removal (principle 2). True removal needs content-stream rewriting: see `ROADMAP.md` |
| 2026-11-16 | The editor shows the page rebuilt as a real PDF after every change; on-screen boxes are only handles | Guarantees what is seen is what is saved, with no second text-layout engine to drift out of step |
| 2026-11-16 | Additions are stored per page, in points from the top-left of the page as the file shows it, before any turn or resize made in the tool | They then turn, resize, duplicate and move with their page, and survive the settings file |
| 2026-11-16 | Added text uses the PDF format's built-in fonts (Helvetica, Times, Courier; regular and bold) | Nothing to embed or download; every PDF viewer has them. Cost: Western European characters only, stated in the page and enforced before saving |
| 2026-11-16 | A picture placed on a page is another fingerprinted source in the settings file, not embedded in it | Keeps the settings file free of content |
| 2026-11-16 | Default output names carry a task suffix (`report-merged.pdf`, `scan-compressed.pdf`). If the visitor's chosen name matches a file they added, the tool stops and asks before saving | Owner's request: never overwrite an original by accident. A web page can't see the visitor's folders, so matching against the names of added files is the check that is possible; the page says so |
| 2026-11-16 | Compress PDF shows the real size of the finished file, plus a before-and-after first page, before anything is downloaded | Owner asked for an "estimate of new size"; the true size is better than a guess (principle 2), and compression is fast enough to just do |
| 2026-11-16 | Default compression shrinks pictures only and never touches text; turning pages into pictures is a separate, clearly warned custom method | Keeps text sharp, selectable and accessible |
| 2026-11-16 | A picture's detail is estimated against its page, erring towards shrinking too little; unusual pictures are skipped and counted, not guessed at | Never damage what isn't understood; say what was skipped |
| 2026-11-16 | A recompressed picture is kept only if smaller, and a file that didn't shrink is not offered for download | Never hand back something worse |
| 2026-11-16 | Compression presets (200/150/100 dpi at 80/65/50% quality) are the tool's own choices | No standard defines them; labelled as such |
| 2026-11-16 | Compression options are stored in the settings file as an optional field; the format version stays 1 | Older files load with compression off; older code ignores the field |
| 2026-11-16 | Interface is task-first, after ilovepdf.com's way of working but in this site's own theme: a home grid of named tasks, each a focused page with one "select files" button, then previews with that task's few options and one action button. No branding, icons or colours are copied | Owner's request. People arrive wanting one job done; a single do-everything page made them find it |
| 2026-11-16 | Every task page is the same workspace (`components/Task.astro`, `web/ui.ts`) configured by `web/tasks.ts`; task pages are hidden from the tab row with `"nav": false` | One engine to test; adding a task is a few lines |
| 2026-11-16 | Tasks asked for but not built are shown on the home grid, greyed and labelled "Not built yet" | Honest about gaps; saves people hunting |
| 2026-11-16 | The PDF standard supplied by the owner is not committed to the repository | Owner's decision: its copyright notice says reproduction needs ISO's permission |
| 2026-11-16 | Office to PDF is on hold (work kept on branch `office-to-pdf`) | Owner's decision; it was unreliable through the service worker |
| 2026-11-16 | Built in phases; phase 1 is page arrangement, images and text. See `ROADMAP.md` | Too large for one pass; accuracy before features |
| 2026-11-16 | A browser security policy (CSP) on the tool page blocks connections to other origins, plus a test that scans the tool's code for network APIs | Makes "never uploaded" enforced and checkable, not just promised; covers third-party libraries |
| 2026-11-16 | The PDF.js worker's code is bundled as text and started from a blob, not from a web address | Measured in Chrome: a page's security policy does not bind a worker started from a web address, so the first published version's claim that the policy covered the libraries was too strong for PDF.js's worker. Blob workers inherit the policy. Corrected within the hour |
| 2026-11-16 | Libraries are npm packages bundled into the site; PDF.js fonts, character maps and decoders are copied to the site by `sync-data` | No CDN or third-party requests (principle 4) |
| 2026-11-16 | Edits are a non-destructive list of pages (`src`, `page`, `rotate`, `scale`) applied when saving | Makes undo, the settings file and testing simple; originals are never altered |
| 2026-11-16 | The settings file holds file names, sizes and SHA-256 fingerprints, never content or passwords; files are matched by fingerprint when re-added | Small, private, and safe to keep or share; detects a changed file |
| 2026-11-16 | Settings are a downloaded file, not kept in the page address or local storage | Departs from principle 4's "settings live in the page address" because the state refers to files, which an address can't carry; file names in an address could also leak into browser history |
| 2026-11-16 | Pages are copied, not re-drawn, when saving as PDF | No quality loss; text stays selectable |
| 2026-11-16 | `@cantoo/pdf-lib` rather than the original `pdf-lib` | The original has had no release since 2021; the fork is maintained and opens password-protected files |
| 2026-11-16 | JPEGs are embedded unchanged and the page is rotated to honour the photo's orientation note | No re-compression loss; phone photos come out upright |
| 2026-11-16 | Named paper sizes (A4, Letter) are not offered yet; resizing is by percentage | Their dimensions need a cited, archived source, which couldn't be downloaded from the build environment |
| 2026-11-16 | SVG output is not offered | PDF.js no longer draws to SVG; wrapping a bitmap in an SVG file would mislead |
| 2026-11-16 | Saved PDFs are not password-protected even if the source was; the tool says so | Writing encrypted PDFs isn't built; silence would mislead |
| 2026-11-19 | Whole-file tasks (Split, Compress, Unlock, Protect, Page numbers, Watermark, PDF to text) show a file list, not page thumbnails | The pages can't be acted on separately there, and hundreds of thumbnails buried the options and the button |
| 2026-11-19 | Page lists are shown a screenful at a time, sized to the screen, rather than as one long scrolling list | Long files stayed usable; fewer thumbnails drawn at once; selection still covers every page |
| 2026-11-19 | Selection starts as "all" for Rotate, Resize and PDF to picture tasks, but "none" for Remove, Extract, Merge and Organise | "All" there only means "use these pages"; for Remove it would delete the lot |
| 2026-11-19 | Crop sets the page's crop box and does not delete anything; the page says so | Content outside stays in the file; calling it removal would mislead (true removal is the Redact chunk) |
| 2026-11-19 | Crop margins are absolute (points, shown in mm, inches or points) and the same on every chosen page | Simple and predictable; a percentage option is a follow-up |
| 2026-11-19 | Resizing scales every page box itself instead of calling the library's `page.scale` | The library resets the crop box to the full page size, which shows the wrong area on any page that is already cropped |
| 2026-11-19 | A drawn signature is placed as a picture and is never stored; the page says it is not a digital signature | A cryptographic signature needs certificates and trust this tool can't provide; storing a signature would break "nothing is kept" |
| 2026-11-19 | Highlight is a see-through coloured rectangle you place, not text-aware | Finding text positions reliably is a separate job; the page says what it is |
| 2026-11-19 | Freehand strokes are stored as shares (0 to 1) of their box | They resize with their box and stay small in the settings file |
| 2026-11-19 | Pictures are never enlarged to fit a page, only shrunk and centred | Enlarging only blurs; the page says so |
| 2026-11-19 | Images to PDF offers a size you type, not named sizes, for now | A4 and Letter dimensions need a cited, archived source first (owner action: see ROADMAP "Sources to archive") |
| 2026-11-19 | Extract pictures copies stored JPEGs out unchanged and writes everything else as PNG | Copying is lossless and exact; PNG keeps every pixel of the decoded data |
| 2026-11-19 | Pictures with CMYK colour, fax-style filters, stencil masks or damaged data are skipped and counted in the message | Converting them wrongly would give wrong colours; saying how many were left out is honest |
| 2026-11-19 | Extract pictures gives the stored picture, without the clipping, scaling or effects the PDF applies when drawing it; the page says so | What is extracted must match what is stored, and the page must not imply it is what the page shows |
| 2026-11-19 | Pictures under 32 pixels on a side are skipped by default (adjustable) and counted | Bullets, icons and rules are not what people want; the count keeps it transparent |
| 2026-11-19 | Repair rewrites the file with the lenient library and says what it found; it never claims to recover content | Only structure (index, header) can be fixed; missing data stays missing, so the message names pages that lost content and files that end early |
| 2026-11-19 | Repair keeps unreadable pages in the saved file and names them, rather than dropping them | Dropping a page silently or by default would destroy possibly-recoverable content; the visitor can remove pages afterwards |
| 2026-11-19 | Compare PDF compares text only, page by position, and says so on the page | Matching pages by content or comparing pixels is a larger job; claiming more would mislead (scans and pictures show no differences) |
| 2026-11-19 | Compare on very long pages reports the page as replaced rather than matching word by word | Keeps the browser responsive; the result states when this happened |
| 2026-11-19 | Text to PDF is its own page, not the shared task page | There are no PDF pages to select or arrange; a text box and page options are all it needs |
| 2026-11-19 | Text to PDF uses the built-in fonts and replaces characters they cannot draw with "?", telling the visitor how many | Embedding a font for other scripts needs a licensed, archived font file; silently dropping characters would be worse |
| 2026-11-19 | Text to PDF starts at 210 × 297 mm typed as numbers, with no named paper size | Named sizes wait for an archived source (see ROADMAP "Sources to archive") |
| 2026-11-19 | PDF to Markdown/HTML guesses structure from text size and line spacing and says so on the page and in the saved-file message | A PDF has no stored headings or paragraphs; presenting guesses as structure would mislead |
| 2026-11-19 | Text is read in the file's own order, not re-sorted into columns | Re-sorting by position misreads more files than it fixes; multi-column pages are listed as a limitation |
| 2026-11-19 | HTML file to PDF is not built | Faithful rendering needs a layout engine; a text-only conversion would not be what the name promises |
| 2026-11-19 | Fill in PDF forms edits the original file's own form (not the page-copy pipeline) | Copying pages into a new file drops the form; editing in place keeps the fields, so the saved file is still a form unless the visitor flattens it |
| 2026-11-19 | Fields with characters the form's font cannot show are left unchanged and named in the message | The library would otherwise fail or draw nothing; saying which field was skipped is honest |
| 2026-11-19 | A PDF with no fillable fields gets a plain explanation and a pointer to Edit PDF, not a guess at where fields might go | Detecting fields drawn as lines is unreliable |
| 2026-11-19 | OCR uses Tesseract via tesseract.js, with the engine, worker and English data copied from the installed packages into the site at build time | Apache-2.0 code, runs entirely in the browser; serving the files ourselves keeps every request on this site (the library's defaults point at a CDN, so each path is set explicitly) |
| 2026-11-19 | OCR adds invisible text over the unchanged page, one stretched word at a time | Keeps the page exactly as it looked (verified pixel-identical) while making it searchable; this is the usual way searchable scans are made |
| 2026-11-19 | OCR asks the engine not to store anything in the browser (cacheMethod "none") | Keeps "nothing is kept" true; the cost is fetching the 3 MB language file again on a later visit (the browser's normal cache may still keep this site's files) |
| 2026-11-19 | Pages whose average engine confidence is below 50 are named as doubtful | In testing, clear scans scored 95+ and a sideways page 37; the message calls it the engine's own score, not a measured accuracy |
| 2026-11-19 | The "no reference files" check skips site/public/tools/, and asserts that folder stays git-ignored | It is build output copied from installed packages (the OCR language file is a .gz), never committed; the assertion stops the skip hiding a committed file |
| 2026-11-19 | OCR offers 40 languages (owner's list plus English), each a Tesseract tessdata_best integer model served from this site | Owner's choice; licence trail recorded in THIRD-PARTY.md (MIT packaging, Apache-2.0 models) |
| 2026-11-19 | Kurdish is offered as Kurmanji (Latin script) only | The Sorani (Arabic script) data exists only for Tesseract's older engine, which would need a second, larger engine build |
| 2026-11-19 | The invisible OCR text uses a font generated by our own code with no glyph outlines | Every script can be searched and copied, and no typeface is reproduced, so there is no font licence to satisfy |
| 2026-11-19 | Right-to-left OCR lines are stored left to right with the letters of right-to-left words reversed | This is how word processors store such text, and both PDF.js and poppler then extract it in reading order (tested); storing reading order made PDF.js reverse it |
| 2026-11-19 | Neighbouring OCR "words" in Chinese, Japanese, Thai, Lao, Khmer and Burmese are joined when under a line's height apart | The engine reports single characters as words; joined, copied text has no stray spaces and phrase searches work. Korean is left as the engine splits it: its gaps inside and between words overlap (measured 0.25-0.34 against 0.50-0.73 of the box height) |
| 2026-11-19 | Every OCR word takes its line's top and bottom | Words of one line then share a baseline, so readers keep them on one line (Korean and Thai were split before) |
| 2026-11-19 | OCR saves nothing when no words were recognised, and says why | A copy with nothing added would look like a success |
| 2026-11-19 | "Your own font": visitors can use a font file from their device for added text; the site ships no font for it | Owner's option 1; no font licence exposure for the site, and the file never leaves the browser |
| 2026-11-19 | Fonts are refused or limited according to their maker's embedding setting (OS/2 fsType) | Respecting the font maker's own technical flag; the page says it is not the licence itself |
| 2026-11-19 | Text in a visitor's font is shaped with HarfBuzz (harfbuzzjs), not fontkit | Owner's option 3, required: fontkit placed the accent of "ó" after "ü" over the wrong letter (366,140 against HarfBuzz's 903,0 font units, FreeSerif); HarfBuzz is what browsers use |
| 2026-11-19 | Bidi order from bidi-js, applied by runs; brackets mirrored by HarfBuzz only | Mirroring in both places flipped brackets twice (seen) |
| 2026-11-19 | Each glyph is placed individually with its own text matrix, from HarfBuzz's offsets (superseded later the same day: runs with adjustments, below) | The PDF library ignores mark positions, which modern fonts rely on |
| 2026-11-19 | Each line is tagged with ActualText, except lines with right-to-left text (superseded later the same day: every line is tagged, below) | Gives the typed words to readers that use it (poppler extracted Hindi, Bengali and Tamil exactly); poppler reversed tagged Arabic, Hebrew and Urdu, which read correctly untagged in both poppler and PDF.js |
| 2026-11-19 | HarfBuzz's cluster level set to "characters" | With the default, glyphs inside merged clusters had empty character maps and PDF.js showed raw codes (letters like Q and W) |
| 2026-11-19 | OCR output in Malayalam is changed to the modern encoding: the five legacy chillu sequences at the end of a word become the single chillu letters, and a non-joiner after a word-final virama is dropped | The engine writes the pre-5.1 encoding, which looks the same but does not match typed searches; mapping from The Unicode Standard 18.0, ch. 12, Table 12-43 (archived). Not changed before another Malayalam letter, where the standard notes the sequence can mean two things |
| 2026-11-19 | A font with the "restricted licence" embedding bit is refused even if another permission bit is also set | The OpenType specification says the bits should never be combined and that some programs then assume the least restrictive; with commercial IP scrutiny in mind, this tool assumes the most restrictive |
| 2026-11-19 | WOFF font files are unpacked to plain TrueType/OpenType in the browser; WOFF 2 is refused with a reason | HarfBuzz reads only plain font data; WOFF 1 is simple zlib per table, WOFF 2 needs a much larger decoder |
| 2026-11-19 | Shipped fonts come from Fontsource's npm packages of Noto Sans (WOFF, one file per alphabet) | Same build pipeline as every other dependency (no committed font files, no download at build time); each package carries the OFL text and copyright line, with no reserved font names |
| 2026-11-19 | Shipped font files are bundled as lazily loaded scripts (base64), not fetched | The tool's code has no network calls (privacy test), and only the alphabets a text uses are loaded |
| 2026-11-19 | A line can mix fonts: each character uses the previous character's font if it has the letter, else the first font that has it; marks and joiners stay with their letter | Fontsource splits each family by alphabet, and real text mixes alphabets (Malayalam with digits and English) |
| 2026-11-19 | Each cluster's characters are mapped to its widest glyph | Noto Sans Arabic draws some letters as a dotless base plus a zero-width dot; mapping the letter to the dot made poppler split "مرحبا" into two words |
| 2026-11-19 | Chinese, Japanese and Korean are not shipped yet | Each family is 3 to 5 MB in about 120 files; deferred to keep this step small. "Your own font" covers them |
| 2026-11-19 | Chinese, Japanese and Korean Noto Sans are shipped as Fontsource's numbered files, with their coverage index loaded only when text needs it | Each family is 3 to 5 MB; a sentence needs a handful of files of about 40 kB, and the 222 kB index stays out of the main page |
| 2026-11-19 | Han characters are drawn in a chosen style: automatic per line (Japanese with kana, Korean with Hangul, otherwise Simplified Chinese), or Simplified, Traditional, Japanese or Korean | The four families draw some shared characters differently (tested: 直 differs between the Chinese and Japanese files) |
| 2026-11-19 | With several fonts, each character goes to the first font that has it (marks and joiners stay with their letter), and fonts are loaded line by line with the same rule | Keeping a character in the previous font, and loading for the whole text, drew "국" from a font that had not been loaded for it (a box) and embedded fonts with no glyphs |
| 2026-11-19 | Spaces are drawn in the font of the text around them, and need no font file of their own | Taking spaces from the Latin file split a Hebrew line into pieces, and PDF.js then gave its words in reverse order; every shipped file has a space glyph |
| 2026-11-19 | Bold in Noto Sans uses Noto's own bold (700) files, loaded only when bold text needs them | The real bold design; all 458 files exist in the same packages |
| 2026-11-19 | Bold in a visitor's own font uses a bold file they add, or else a simulated bold (letters filled and outlined, the outline 3% of the text size), and the page says which | Without a bold file there is no real bold to use; outlining is the usual way PDF software simulates bold, and saying so avoids presenting it as the font's design |
| 2026-11-19 | Urdu is drawn in Nastaliq (Noto Nastaliq Urdu, OFL) when a line uses a letter of Urdu that Arabic and Persian lack (ٹ ڈ ڑ ں ھ ہ ۂ ے ۓ); otherwise Naskh; either can be chosen for all Arabic-script text | Nastaliq is how Urdu is normally printed; Persian and Arabic use Naskh. Letter-based detection keeps a mixed page right without a language setting, and the choice covers text the rule gets wrong |
| 2026-11-19 | Text lines are spaced by the tallest font the text uses (ascent plus descent of every font loaded) | Nastaliq lines overlapped when the height came from the Latin font only. Other text gets more space than before where it uses tall fonts (Malayalam, Devanagari) |
| 2026-11-19 | Glyphs are written as runs with spacing adjustments (TJ), marks raised or lowered with the text rise, instead of one positioned glyph at a time | Readers see continuous words; rendering is unchanged (three earlier test files compared pixel by pixel: no glyph moved) |
| 2026-11-19 | When one glyph is drawn for different letters, it is stored again (a copy of the outline under a new id) so each copy maps to its own letters | Noto Sans Arabic and Noto Nastaliq Urdu draw ب/ت/ث, ح/خ, ر/ڑ on shared dotless bases; one map entry per glyph gave wrong letters on copying (poppler gave "حدا" for "خدا", "ہون" for "ہوں"). The font library's cached glyph objects kept the letters of their first use, so they are not used for the map. Checked with TrueType and CFF fonts |
| 2026-11-19 | Glyphs that stand for no letter (dots, extra parts of a cluster) map to U+2060 WORD JOINER | Unmapped or empty-mapped glyphs came out as control characters in PDF.js, PDFium and MuPDF (they fall back to the glyph number); PDF.js skips format characters; format characters are transparent to Arabic joining. Cost: readers that use neither the tag nor bidi (pdfminer) include invisible word joiners |
| 2026-11-19 | Every line is tagged with ActualText in reading order, right-to-left lines included | PDF defines ActualText as the replacement text; on 15 test lines in 12 scripts PDFium (Chrome, Edge) went from garbled right-to-left lines with control characters to 15/15 exact. Cost: poppler and MuPDF reverse tagged right-to-left lines (6/15 each; on 6 of the lines poppler gave 4 untagged and 1 tagged). PDFium is by far the most used of the tested readers; Acrobat and Preview untested. Recorded in VERIFICATION.md and on the methods page |
| 2026-11-19 | Rejected: turning off the fonts' glyph decomposition (ccmp) so each letter is one glyph | HarfBuzz then gave isolated letter forms (no joining) in Noto Sans Arabic |
| 2026-11-19 | Rejected: writing glyphs in reading order and placing each one | PDF.js lost the spaces between words and MuPDF garbled lines further |
